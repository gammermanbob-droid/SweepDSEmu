SweepDSEmu — Startup Guide
===========================

SweepDSEmu is a fork of Azahar (3DS emulator) with an integrated melonDS
core, letting DS/DSi titles run alongside 3DS titles — including as real
installable forwarder CIAs that appear as normal icons on the emulated
3DS HOME Menu and boot straight into the DS game.

This guide covers two ways to run it:
  1. macOS   — build from source and run natively.
  2. Windows — either download the CI-built .exe, or build it yourself
               on Windows, then run it under Wine (or natively on
               Windows/in a VM).

If anything below doesn't match what you see, check the repo's own
.ci/ folder (.ci/macos.sh, .ci/windows.sh) — that's the exact script
GitHub Actions runs, kept in sync with the real build.


===========================================================
1. macOS — BUILD FROM SOURCE
===========================================================

Prerequisites
-------------
- Xcode Command Line Tools
- Homebrew
- CMake, Ninja, Qt6, Boost, SDL2, and the other deps Azahar needs

Commands
--------
  # 1. Install Xcode Command Line Tools (skip if already installed)
  xcode-select --install

  # 2. Install Homebrew (skip if already installed)
  /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

  # 3. Install build dependencies
  brew install cmake ninja qt@6 boost sdl2 ffmpeg openssl zstd \
      pkg-config ccache

  # 4. Clone the repo (or use your existing local checkout)
  git clone --recursive https://github.com/gammermanbob-droid/SweepDSEmu.git
  cd SweepDSEmu

  # 5. Configure and build (mirrors .ci/macos.sh)
  mkdir build && cd build
  cmake .. -GNinja \
      -DCMAKE_BUILD_TYPE=Release \
      -DENABLE_QT_TRANSLATION=ON \
      -DENABLE_ROOM_STANDALONE=OFF \
      -DUSE_DISCORD_PRESENCE=ON \
      -DUSE_SYSTEM_QT=ON
  ninja

  # 6. Build the distributable, self-contained .app bundle
  #    (bundles Qt/library dependencies via macdeployqt — this is the
  #    one you actually want to run/distribute, not the raw bin/Release
  #    executable, which expects your build machine's exact library
  #    paths)
  ninja bundle

  # 7. Run it
  open build/bundle/azahar.app

IMPORTANT: pass -DUSE_SYSTEM_QT=ON on macOS
--------------------------------------------
Without this flag, the build downloads its own private copy of Qt
(via aqtinstall) to build against, but the "ninja bundle" step still
uses your system's Homebrew macdeployqt tool to package it — if you
also have Homebrew's qt@6 installed (likely, since it's a listed
dependency), that mismatch causes the built .app to crash on launch
with a dyld symbol error (QtConcurrent/QtCore version mismatch).
-DUSE_SYSTEM_QT=ON makes the whole build and the bundling step use
the one Homebrew Qt install consistently.


First-run setup specific to SweepDSEmu (DS support)
----------------------------------------------------
- Put your .nds ROMs under the emulated SD card at:
    ~/Library/Application Support/AzaharPlus/sdmc/roms/nds/
- For a TWiLightMenu++/nds-bootstrap style DS menu (browse DS games
  from within the emulator, not just Azahar's own list), drop
  nds-bootstrap's BOOT.NDS and its supporting folders directly onto
  that same SD card root (~/Library/Application Support/AzaharPlus/sdmc/).
- To make a DS game (or BOOT.NDS itself) show up as a real icon on the
  emulated 3DS HOME Menu, use the forwarder generator:

    python3 tools/make_ds_forwarder.py "/path/to/game.nds" \
        --output-dir ~/Desktop/forwarders \
        --user-dir "~/Library/Application Support/AzaharPlus/"

  Then install the resulting .cia through Azahar's own
  File > Install CIA (or headlessly: azahar --install path/to/game.cia).
  Optional: pass --title "Custom Name" to override the icon's title
  (useful for homebrew like BOOT.NDS that don't have a clean built-in
  name).


Optional: real DSi system files, for TWiLightMenu++/MoonShell SD access
-------------------------------------------------------------------------
Without real DSi system files, SweepDSEmu runs DS titles with FreeBIOS
and a generated firmware (fine for regular games), which only gives
homebrew DLDI-based "slot-1" SD card access. TWiLightMenu++ and
MoonShell 2 are DSi-enhanced titles that expect the DSi's own native
SD/SDIO controller instead, which only exists once a real, genuine
DSi console's dumped BIOS/firmware/NAND are supplied — without them
they'll boot but report "no SD card inserted" (this happens on the
official melonDS app too, for the same reason). This is NOT a bug in
this emulator; it's accurate to how a real DSi behaves.

If you own a DSi and have dumped your own console's files (e.g. via
GodMode9i), drop these seven files, renamed exactly as below, into:
    ~/Library/Application Support/AzaharPlus/sdmc/bios/
(or the equivalent sdmc/bios/ folder for whichever platform you're on
 -- see the platform-specific sections below for exact paths)

    bios9.bin          <- your regular DS ARM9 BIOS      (4 KB)
    bios7.bin          <- your regular DS ARM7 BIOS       (16 KB)
    firmware.bin       <- your regular DS firmware        (256 KB)
    dsi_bios9.bin      <- your DSi ARM9i BIOS              (64 KB)
    dsi_bios7.bin      <- your DSi ARM7i BIOS              (64 KB)
    dsi_firmware.bin   <- your DSi firmware                (128 KB)
    dsi_nand.bin       <- your full DSi NAND dump          (~240 MB)

All seven must be present together for DSi mode to activate -- with
only the first three, DS titles still boot fine, just without native
SDIO access. Once all seven are in place, launching a DSi-enhanced
homebrew title (like TWiLightMenu++'s BOOT.NDS) boots through the
real DSi Menu on your dumped NAND instead of a direct-boot shortcut,
exactly like real hardware, and TWiLightMenu++/MoonShell get real SD
access.

IMPORTANT: these are dumps of YOUR OWN physical console and are
personal/non-redistributable -- never commit them to this repo, share
them, or bundle them in a release. Each user must supply their own.
The dsi_nand.bin file is also written to during emulation (titles,
saves, system settings), so treat the copy you place here as a live
working copy, not your archival backup.


===========================================================
2. WINDOWS (via Wine, or a real Windows machine/VM)
===========================================================

IMPORTANT: use the MSYS2 build, not MSVC
------------------------------------------
The CI (.github/workflows/build.yml) builds Windows two ways — MSYS2
(a Clang/MinGW toolchain) and MSVC (Microsoft's own compiler). Only
MSYS2 actually works right now: melonDS's own upstream source was
only ever built with GCC/Clang (its own Windows builds go through
MinGW too, never MSVC) and leans on GCC/Clang-only constructs deep
inside its x64 JIT compiler that MSVC's parser can't handle. Several
of these have been patched already (see cmake/melonds.cmake's MSVC
compat header), but new ones keep surfacing further into the JIT
backend, so MSVC support is left unfinished for now. Use the MSYS2
build/artifact — it's a real, fully working Windows .exe.

Option A — Download the CI-built .exe (recommended)
-------------------------------------------------------------------
  1. Go to: https://github.com/gammermanbob-droid/SweepDSEmu/actions
  2. Open the latest successful build.yml run for your branch.
  3. Under that run's "windows (msys2)" job, download its build
     artifact from the run's "Artifacts" section — a zipped bundle
     containing azahar.exe and all its DLLs. Do NOT use the
     "windows (msvc)" artifact/job — see above.
  4. Unzip it somewhere, e.g. ~/SweepDSEmu-windows/

Option B — Build it yourself on Windows via MSYS2 (mirrors .ci/windows.sh)
-------------------------------------------------------------------
  1. Install MSYS2 (https://www.msys2.org/), then open a "CLANG64" shell
     from its Start Menu group (not the default MSYS2/MINGW64 one).
  2. Install the toolchain and dependencies:
       pacman -S --needed $MINGW_PREFIX-toolchain $MINGW_PREFIX-ccache \
           $MINGW_PREFIX-cmake $MINGW_PREFIX-ninja $MINGW_PREFIX-spirv-tools \
           $MINGW_PREFIX-qt6-base $MINGW_PREFIX-qt6-multimedia \
           $MINGW_PREFIX-qt6-multimedia-wmf $MINGW_PREFIX-qt6-tools \
           $MINGW_PREFIX-qt6-translations $MINGW_PREFIX-zlib $MINGW_PREFIX-zstd
  3. From that same CLANG64 shell, in the repo root:
       mkdir build
       cd build
       cmake .. -G Ninja \
           -DCMAKE_BUILD_TYPE=Release \
           -DENABLE_QT_TRANSLATION=ON \
           -DUSE_DISCORD_PRESENCE=ON
       ninja
       ninja bundle

  The finished app is at build\bundle\azahar.exe (plus its DLLs in the
  same folder — copy the whole bundle folder together).

Running it under Wine (macOS or Linux)
-----------------------------------------
  # 1. Install Wine (macOS via Homebrew)
  brew install --cask wine-stable
  # or on Linux: use your distro's wine package / WineHQ repo

  # 2. Set up a Wine prefix (first time only)
  WINEPREFIX=~/.wine-sweepdsemu winecfg

  # 3. Run the built/downloaded Windows bundle
  WINEPREFIX=~/.wine-sweepdsemu wine "/path/to/SweepDSEmu-windows/azahar.exe"

Important caveat: SweepDSEmu (like upstream Azahar) renders via Vulkan.
Wine's Vulkan support depends on your platform's translation layer
(DXVK/vkd3d on Linux, or MoltenVK-backed passthrough on macOS via
something like a Game Porting Toolkit setup) and is not guaranteed to
work — if the window opens but nothing renders, or it crashes on boot,
that's a Wine/Vulkan compatibility issue, not a bug in the emulator
itself. A real Windows install or VM (Parallels/UTM/Boot Camp) will be
far more reliable for actual testing.

First-run setup specific to SweepDSEmu (DS support), Windows edition
------------------------------------------------------------------------
Same as macOS, just with Windows-style paths — Azahar's user data
directory on Windows is normally:
    %APPDATA%\AzaharPlus\sdmc\roms\nds\
(or wherever you configured it in Emulation > Configure > System >
"Filesystem" if you changed the default user data location).

The optional real-DSi-system-files setup above works the same way here
— drop the same seven renamed files into:
    %APPDATA%\AzaharPlus\sdmc\bios\

Android: the equivalent folder is sdmc/bios/ under the app's storage
location (Settings > System > "Filesystem" in-app shows the exact
path; by default something like
/storage/emulated/0/Download/AzaharPlus/sdmc/bios/, or wherever the
app's data directory was set to on your device) — push the same seven
renamed files there (e.g. via `adb push` or a file manager) for
TWiLightMenu++/MoonShell SD access on Android too.

The forwarder generator (tools/make_ds_forwarder.py) is a plain Python
script and needs bannertool/makerom/devkitARM's Windows builds — see
tools/make_ds_forwarder.py --help for the exact flags to point it at
those tool paths on Windows.
